`oldProfileCredentialsUsed: false`, and
`remainingRisk: "arbitrary-old-profile-not-attestable"`, alongside real procedure
records/traces. A checkbox, successful unregister call, fresh-tab screenshot, or

## Activation ordering and failure handling

Run the approved sealed runner in its own systemd unit outside the gateway, with
adequate timeout; do not use a gateway child process or the heavy-test unit for a
production watcher. No unit has been created or armed by this task.

1. Validate seal/evidence/authority/dependencies and fresh immutable baselines.
2. Call the sealed OLD authenticated watcher with `--check` twice, five seconds
   apart. Require full ALL-thread coverage, idle, and zero pending; unknown/error/
   pagination fail closed. Wait bounded to twelve hours; recheck drift each loop.
3. Private backups; put admin into no-store 503 and previews into parked HTTPS.
   Old readiness uses direct loopback and remains available. Recheck all baselines,
   dependencies and a third ALL-idle/zero-pending immediately before copy.
4. Copy assets without deleting old hashes. Atomically rename each allowlisted
   backend file and verify the complete backend including excluded files/Hours.
5. Activate exact staged dependencies and merge only six nonsecret env settings
   while preserving login secrets/workspaces/root/fullAccess. Mandatory encryption.
6. Run the sealed OLD watcher with the private original env. It does its own dual
   ALL-idle check and exactly one restart. Never call the new adapter on old runtime.
   The runner monitors drift and stops only its own watcher on failure.
7. Prove a fresh actual PID/cwd/entry command and backend hashes, then use the new
   encrypted maintenance adapter. Activate reviewed Workboard, publish index last,
   enable isolated ingress, and verify full local/public bodies.
8. Postverify encrypted proof, cookie-only legacy rejection, Files/Services/Hours
   read-only APIs, decrypted stream first record, Workboard headers, excluded modules,
   old assets and Hours generator/template. Revocation/preview ticket mutations
   remain exact-app isolated-fixture evidence: no production model/pause/logout or
   ticket creation is used as a test. If actual live ticket/revocation mutation is
   required, obtain a specifically scoped later verification plan.
9. Only after publication proof update Services and a new checked-revision Vault
   publication reference. A failed bookkeeping step retains actual publication
   evidence and a failed phase; it does not masquerade as an unperformed rollout.

File replacement is atomic per file, **not** a cross-file transaction. The gated
old process retains its loaded modules until the watcher restarts it. Partial
copies/restart failures retain `attempt.json` phase and installed-file list. There
is no retry, automatic downgrade, DB restore, old same-origin proxy, or plaintext
recovery mode. Keep public ingress gated on failure and have the leader review
exact state before a new candidate/release. A failure after reopening ingress
needs explicit containment using the sealed maintenance/parked configs; the runner
does not blindly undo a potentially concurrent operator change.
