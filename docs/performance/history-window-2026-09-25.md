## Read boundary and native compatibility

Saved generated protocol `/tmp/codex-orchestration-protocol/v2/{ThreadReadParams,ThreadItemsListParams,ThreadTurnsListParams,ThreadTimelineListParams,Thread,ThreadItem}.ts` was inspected. `Thread.path` supplies the persisted rollout path; `thread/read includeTurns:false` and `thread/turns/list itemsView:notLoaded,limit:1` supply bounded metadata. The item/timeline APIs have item-count pagination but no content byte limit in those schemas. They cannot safely retrieve an arbitrarily large item before clipping. Installed native0.155.0 oracle execution below verifies these used methods and response shapes against owned persisted fixtures; no claim is made about other installed versions.

`/history` now issues **two metadata RPCs per paginated page** (one for explicit legacy mode), zero `thread/items/list`, zero full `thread/read`; detail issues one metadata RPC. The latest native turn status is authoritative even when its JSONL completion record has not flushed. Startup/resume, selected-view consistency and unread reconciliation can each request pages; do not equate two RPCs per page with two total RPCs per browser open. Resume retains `excludeTurns:true`. Background Vault completion repair still has its pre-existing full hydration path; this patch does not claim to eliminate every internal full read.

Content comes from a new private read-only incremental index of trusted native `sessions`/`archived_sessions` JSONL. No user-provided paths; authorize thread/workspace first, resolve under native storage, open nonblocking/O_NOFOLLOW, verify regular FD canonical path, then verify session_meta thread ID/cwd. Recheck descriptor/current path identity and liveness after reads. Cursor contains HMAC-bound thread, generation and positions, never a filesystem path.

Parser consumes fixed 64 KiB blocks; it does not collect a raw JSONL line. Normal string prefixes retain at most16 KiB, aggregate normal strings64 KiB, containers64 entries/2048 nodes/depth64; identity fields are separately bounded. The unretained string tail still checks delimiters/escapes/control bytes using bounded block scanning. Known messages project to valid text/content objects; tools project to typed summaries, preserving IDs rather than recursively replacing fields with null. Unknown tool structures remain available as original record ranges. Internal reasoning/system/developer records are not expanded into the transcript.

`history-paginated.ts` now projects paginated records separately, before the legacy reducer. Only `item_completed` with its explicit native thread/turn/item identity creates an item. Raw `response_item`, `turn_context`, `item_started`, and dedicated legacy messages do not create a second display stream. Canonical message IDs survive unchanged for cache/SSE reconciliation; AgentMessage `content: [{type: "Text", text: ...}]` parts concatenate as native text, retaining final/commentary phase. Hidden reasoning/internal channels do not render or count. Lifecycle events address only their explicit turn; no assignment to the previous or next turn is guessed. Materialized items can precede lifecycle metadata: they keep that explicit turn ID with unknown status until its lifecycle appears. Duplicate completed items preserve their first position while updating their bounded snapshot; cursor generation changes. Materialized turns retain their first position and first terminal outcome.

Checkpoint v3 stores mode and next native ordinal together with the same committed byte position and derived rows. Earlier derived indexes rebuild; native data is never rewritten. Unreferenced paginated records require contiguous safe ordinals starting at zero, including the header. Missing/regressed/gapped ordinals fail visibly instead of silently renumbering. This is deliberately stricter than the inspected upstream materializer's warning/skip recovery; corrupt-source recovery parity is not claimed. Cancellation checkpoints and mode/ordinal persistence have passing regressions and native checkpoint/restart/append comparisons.

Rollback is format-specific. In paginated mode, `thread_rolled_back` and model compaction context do not delete materialized display records. Native paginated reverts may switch to a replacement rollout with a referenced prefix; inode/path changes invalidate or isolate the derived index. **Non-null `history_base` or `subagent_history_start_ordinal` remain unsupported and fail before returning partial history.** This candidate covers the unreferenced metadata reported for Chung, not every fork/revert lineage. Compressed/reference-based histories need a compatible reader before enabling them.

Legacy mode retains its separate `ThreadHistoryBuilder`-style reducer: dedicated messages use native `item-N` counters; implicit turns use `rollout-N` record positions. Its rollback affects only derived rows and invalidates cursors; compaction replacement model context is not a new user message. Its synthetic control fixture intentionally contains legacy events and is labeled accordingly. Hook XML support and other legacy renderer/event limits from the earlier candidate remain; this is a bounded display projection, not a complete native renderer port.

## Bounded work, cache and detail

- A page selects20 message records, at most60 associated tool summaries, and a counted tool-range entry when additional tools exist. Older cursor cuts at message boundaries without losing the intervening tool range. Partial turns retain turn IDs/status. Each selected tool snapshot retains an authenticated source range; an upserted tool’s earlier lifecycle snapshots are not a separate audit-history API.
- Detail reads at most32,768 UTF-8 bytes directly from the verified FD; next/back use actual byte offsets, trim incomplete UTF-8 suffixes and keep128 back positions. No repeated native whole-item fetch. Updated single-record positions and rewritten-generation cursors fail visibly.
- Node22 built-in SQLite stores bounded projections in a private0700 directory/0600 files, 2 MiB SQLite page cache, maximum128 MiB per thread DB, one active index job and at most16 queued jobs. All SQL result arrays are limited to a page; checkpoint transactions occur at complete-record boundaries after about1 MiB. A single huge incomplete record is reparsed after cancellation; no mid-record checkpoint claims.
- Cold index still scans the complete source once, with bounded working memory. Warm unchanged open reads small head/tail guards (up to8 KiB) and queries the index. Append scans only the new suffix (plus an incomplete tail); persistent checkpoints survive restart. Truncation, inode replacement, same-size mtime change and head/tail mismatch rebuild a new generation. A concurrent append may be picked up next revalidation. This is cooperative consistency, not detection of malicious-root in-place rewrite+append preserving identity/anchors. Invalid/corrupt cache or exhausted disk cap fails visibly; no native-state restore. Per-thread disk cap does not constitute a global cache-disk quota.
- Cold opening can also trigger existing unread-gap reconciliation of other conversations. Those reads are now metadata/index reads, not full native hydration, but first-time index construction and unread-gap work still cost disk/CPU. Measurements must report actual total requests and index bytes, not just HTTP body size.
- Fresh owner/session proof precedes cached plaintext reuse on each unlock. Warm device cache paints before history network revalidation; unchanged encrypted responses use existing revision/unchanged protocol; append sends only a bounded current window. This is bounded-window replacement, not a bespoke per-item patch protocol. Already-unlocked offline browsing reuses cached pages. Cold offline unlock is intentionally not enabled.
- Upward wheel/touch/keyboard at the boundary retrieves one page; there is no automatic older-page drain. Stable item anchors preserve reading position; DOM caps240 items. Paused readers retain their window while latest cache updates. Native rewrite invalidates old cursors without moving the reader; explicit latest reload remains available. Pending/Plan/drafts/live authority remain separate. Lock/switch aborts or discards stale work.
