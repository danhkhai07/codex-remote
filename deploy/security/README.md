# Security release prerequisites (not installed)

These are reviewable configuration candidates, not a claim of production hardening.

1. Provision proxied DNS for `p{port}.danhkhai.io.vn` (explicit records for approved ports, or wildcard `*.danhkhai.io.vn`) pointing to this VPS, and TLS covering those hosts at both Cloudflare edge and Nginx origin. Current `codex.danhkhai.io.vn` certificate has only that exact SAN; `p5180.danhkhai.io.vn` did not resolve at preparation. Do not disable TLS verification or reuse that single-name certificate. No credentials/DNS/TLS resources were changed here.
2. Review/install the Nginx vhosts using `codex-nginx.conf.example` and `cloudflare-real-ip.conf`. Merge with the existing vhost rather than duplicating its listeners. Keep existing TLS options/DH params and HTTP redirects. Verify `nginx -t`, backup exact current config and hashes first. No production reload in this task. The app trusts only explicit loopback peers and X-Real-IP; Nginx overwrites it with the address derived only from Cloudflare's official source networks. Direct non-Cloudflare clients cannot supply their own CF-Connecting-IP. This does not restrict which peers can connect at the firewall.
3. Merge ONLY nonsecret settings in `environment.example` into `.env`, with baseline check and root-only backup; never copy example over credentials. The gateway must not start the new code with old FILE_ROOTS=/; it fails closed. Workspaces and existing full-access choices are unchanged. File browser exposes allowed folder shortcuts. Add other project directories explicitly if needed; no root/system or auth directories.
4. Workboard is a separate app at `/root/GITHUB/Workboard`, port5180. Its own cookie/session is independent. Move its admin-origin Nginx path to the provided preview redirect. The Codex proxy rewrites incoming validated Origin to `http://127.0.0.1:5180`, so set `WORKBOARD_ORIGIN=http://127.0.0.1:5180` for that service. For embedding, the prepared `workboard-embedding.patch` preserves its default frame policy and optionally permits `WORKBOARD_FRAME_ANCESTOR=https://codex.danhkhai.io.vn`; this requires a separate reviewed Workboard commit/build/restart, not editing its live checkout. Without that patch it supports the isolated external tab but its own CSP intentionally blocks cross-origin iframe embedding. Reauthenticate Workboard on the new host. Do not copy its user state or cookies to test fixtures.
5. Migration: new HTTPS sessions use `__Host-codex_remote_session` and signed credential-generation data; browsers must log in again. Before signing back in, close old `/preview/` and `/workboard/` tabs. The new client unregisters those legacy scoped service workers while retaining the app worker and drafts. Unregistering cannot terminate an already open hostile document; this patch is prevention, not a claim to remediate an established browser compromise. No blanket localStorage/cache purge is performed. Password/signing-key changes on restart invalidate old browser and preview grants; this task rotates neither.
6. Keep `CODEX_REMOTE_SESSION_STATE` outside file roots and preserve it across deploy/restart. Atomic revocation writes are owned by one gateway process. The deployment/restart watcher uses both cookie names only for local maintenance, and can pin this release's auth module with `CODEX_REMOTE_DEPLOY_AUTH_MODULE` for transition/rollback. Tokens stay in memory. Concurrent independent gateway writers to the same state file are unsupported.
7. Backend rollout only after ALL native turns and pending inputs are idle, using `scripts/restart-when-idle.mjs`. Pin main/source/runtime/frontend hashes and PID; abort on drift. Copy only the manifest allowlist of app-security modules/maps, preserving `work-hours.js` SHA a9a74ac46cd4c72b5ff350188d3edf648d8b4ffe2a5fbf4a494f68fab691bd91 and excluded backend modules. Retain old hashed client assets and atomically publish index.html last. Verify both origins, current auth/isolated preview/WS and workboard, health, new PID and hashes before marking live. Services/Vault updates follow actual verification.

## Residual boundary

Gateway and agent remain root. No fullAccess downgrade, stop/cancel, root-user separation, firewall/SSH/kernel operation is part of this patch. Allowroots plus filename/canonical-path checks block common API secret/system routes and symlink swaps, but do not classify every secret in arbitrary project text, defeat root-created hard links, or restrict a full-access agent. `.env.example/.sample/.template` are deliberately readable documentation. A separate user/executor migration needs inventory of writable workspaces, subprocesses, Docker access and secrets; a docker-group user is still effectively host-root. Plan that migration independently.
